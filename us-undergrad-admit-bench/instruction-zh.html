第一部分：从零安装

1. 准备环境

确认电脑已安装 Node.js 18 或更高版本。Pilot 使用 Node.js 22.20.0。

2. 解压仓库

将压缩包解压到一个固定位置。不要直接在压缩包预览中运行。

3. 安装依赖

在仓库根目录安装依赖。

cd us-undergrad-admit-bench-main
npm install

4. 确认关键文件

检查 README.md、SKILL.md、config/profile.yml、modes/、scripts/、corpus/、reports/ 与 data/ 是否存在。

完成标志 目录齐全，npm install 没有阻断错误。

第二部分：建立学生 Profile

对学生基本情况进行梳理，建立档案，方便择校时的信息对比

1. 录入基础成绩

把 GPA、SAT/ACT、所在国家、申请阶段写入 config/profile.yml。SAT 分项必须有明确标签。

student:
stage: high_school
country: China
academics:
gpa: "95/100"
sat:
total: 1520
math: 800
ebrw: 720

必须回读确认 请确认：SAT 1520 = Math 800 + EBRW 720。Pilot 第一次把顺序写成 720 + 800，程序没有报错，反而生成了错误结论。



2. 补充课程、活动与预算

本次正确测试数据包括 5 门 AP（Calculus BC、Physics C: Mechanics、Microeconomics、Macroeconomics、U.S. History，均 5 分）、Ross 数学营、斯坦福夏校、模拟联合国，年度预算 $200,000，不需要资助。

3. 只保存真实事实

对话中为了测试补造的 Euclid Honour Roll、哲学论文、AI & Philosophy Reading Lab 都必须放入测试 fixture，不能进入真实申请档案。

数据卫生 正式使用前，搜索 DEMO / SYNTHETIC / TEST DATA，并删除或隔离所有虚构事实。

第三部分：Admit Band 成绩校准

统计目标学校往年录取的官方成绩区间，判断自己的录取概率

1. 准备输入

SAT/ACT + 至少一所点名学校即可运行；GPA、预算和活动不是本功能的必填项。

2. 运行校准脚本

在仓库根目录执行：

npm run admit-band

3. 打开结果

打开 reports/admit-band-YYYY-MM-DD.html；同时保留同名 JSON 作为机器可读证据。

完成标志 HTML 中出现学校的 25th / median / 75th 位置标签；JSON 可正常解析。



4. 正确解读

本次 1520、Math 800、EBRW 720 对 Michigan 的校园整体区间显示：总分接近 75th，数学高于 75th，阅读写作接近中位。

不要这样说 不要把“above p75”写成录取率或“稳录”。它不是 CS 专业单独统计，也不代表个人概率。



真实输出证据 Pilot 生成了 outputs/your-admit-band-2026-08-24.html、notre-dame-admit-band.html 以及相应 JSON。

第四部分：学校 A–J 完整评估

将学校对录取学生的要求进行全方位评估，结合个人信息判断学生处于申请者中的什么位置

1. 提供完整申请画像

学校、专业、GPA、课程难度、1–3 项关键活动、预算、是否需资助和校园偏好越完整，A–J 越可靠。

可以直接这样说 请详细评估 University of Michigan–Ann Arbor 的 Computer Science。我的 GPA 95/100，SAT 1520（Math 800，EBRW 720），5 门 AP 均 5 分，每年预算 20 万美元，不需要资助。



2. 检查 A–J 十个模块

学校概况、学术、录取、财务、职业、文化、地点、项目深度、成长机会、主观匹配必须齐全，并附官方来源。

3. 检查分类与总分

Michigan CS 结果为 Reach、4.4/5；Notre Dame Philosophy 为 Hard Reach、4.2/5。分类不能被高 SAT 自动改成 Match。

4. 核验时效性

截止日、费用、项目规则和奖学金要求在正式提交前必须重新访问官网核验。

真实输出证据 outputs/密歇根大学安娜堡-CS-中文测试报告.md；outputs/002-圣母大学-哲学专业-中文测试报告.md。

第五部分：比较两所学校

若出现在两所学校中犹豫的情况，可对二者全方位进行对比，选出最适合的一所

1. 先确保至少一所有完整评估

本次比较 Michigan 与 Wisconsin–Madison 的 CS；Michigan 有 A–J 报告，Wisconsin 仅有公开数据，因此后者必须标记 provisional。

可以直接这样说 比较密歇根安娜堡和威斯康星麦迪逊的 CS，重点看录取定位、课程、就业、成本和校园环境。



2. 检查证据状态

每个分数应说明是 evaluated、public_data_only、missing 或 stale，不能把临时公开数据包装成完整评估。

3. 输出决策建议

比较应说明各自适合谁、主要取舍和下一步，而不是只给总分排名。

第八部分：Essay Assistant

为文书撰写提供素材与思路的协助

1. 提供真实题目与素材

至少提供 Essay Prompt、真实事件、细节、你的反思和表达习惯。

2. 素材不足时停下

本轮测试正确停留在 v0 提纲和 needs_student_material，没有把虚构论文写成可提交文书。

3. 按状态推进

建议使用：needs_student_material → outline → draft → voice_pass → final_review → final。

红线 系统可以整理和追问，但不能为学生创造奖项、研究、观点转变或个人经历。

第九部分：Scholarship Evaluation

根据学生提供的信息，多维度评估获得奖学金的概率

第十部分：Financial Aid Letter Parser

为学生是否能获取经济资助提供帮助和咨询

1. 提供完整资助信

包括学校 COA、grant/scholarship、work-study、loan、家庭支付和条款。隐私信息应先遮盖。

2. 先判断身份资格

国际 F-1 学生通常不能使用 Pell、Federal Work-Study、Direct Loan 或 Parent PLUS；必须先判断，再做预算。

3. 拆分资金类型

Gift aid、Work、Loan、Family cash 必须分开；贷款不属于 aid。

4. 正确计算

Net Price = COA − gift aid；Work-study 作为学年内潜在收入单列，不能直接减少开学前应付金额。

利率时效 Mode 中曾硬编码旧利率。每次都要按首次放款年度从官方来源重新核验。

第十一部分：Pipeline 批量处理

1. 把项目写入队列

在 data/pipeline.md 中加入要处理的学校或奖学金。

2. 由 Agent 分类并执行

当前 Pipeline 不是一键程序；分类、调用 Mode、研究和生成报告由 Agent 编排。

3. 合并并验证

辅助脚本负责把 additions 合入 Tracker，并检查状态、重复和报告链接。

npm run merge
npm run verify

4. 确认结果

本轮 Pipeline 更新 1 项、新增 1 项，无重复；最终 verify 为 0 errors、1 个预期 fixture warning。
