01 / Choose the input path

Start from evidence, not protocol memory.

The skill first classifies the material. That choice controls how participants, message ordering, and cryptographic meaning are recovered.

02 / Extraction pipeline

Five gates between input and diagram.

The workflow favors completeness and semantic correctness over decorative brevity. Every distinct message and known failure path belongs in the result.

GATE 01 Classify Code, spec, both, or ambiguous.
GATE 02 Locate roles Participants, orchestration, rounds.
GATE 03 Trace messages Sender, receiver, payload, order.
GATE 04 Annotate crypto DH, KDF, signatures, MACs, encryption.
GATE 05 Verify delivery Directions, phases, aborts, syntax.
What to include

Point to the evidence and define the comparison.

For the strongest result, provide the source directory, the governing spec when available, the protocol name, and any deployment boundary that turns local calls into real network messages.

04 / Scope and operating limits

Use it to reason about flow—not to certify security.

This is an agent-guided semantic extraction workflow. It can surface missing checks and implementation/spec divergences, but it is not a deterministic parser or a formal proof engine.

Best fit

Protocol understanding

  • Handshake and key-exchange reviews
  • Code-to-spec comparisons
  • MPC and multi-party round mapping
  • Security-review communication
Human review

Ambiguity remains visible

  • Inferred ordering must be labeled
  • Underspecified crypto stays flagged
  • Complex implementations need source coverage checks
  • Rendered syntax should be verified when a renderer exists
Out of scope

Do not overclaim

  • Not a call-graph generator
  • Not formal protocol verification
  • Not proof of cryptographic security
  • Not guaranteed 100% extraction
