What it does

A repeatable review conversation.

Skill Vetter makes pre-install review harder to skip. It tells the host agent what to inspect and gives the final decision a consistent structure. It does not execute a malware engine, sandbox a package, or prove that unseen runtime behavior is safe.

Source context

Records publisher, repository, release age, popularity, and available reviews.

Capability inventory

Surfaces file access, network destinations, shell commands, secrets, and elevated permissions.

Decision record

Produces a compact report with red flags, risk level, verdict, and notes.

Protocol

Four checks before trust.

The original Skill is deliberately procedural. The reviewer should read all files, keep fetched content untrusted, and ground each conclusion in what the package actually requests or executes.

01 / SOURCEEstablish provenanceIdentify origin, publisher, maintenance, and public signals.
02 / FILESRead the packageInspect every executable, manifest, config, and instruction file.
03 / SCOPEMap permissionsList files, commands, network destinations, and sensitive access.
04 / VERDICTClassify riskChoose low, medium, high, or extreme, then explain why.

Review focus

Ask what does not fit.

High-risk capability is not automatically malicious; it becomes a stronger concern when access exceeds the claimed purpose, is hidden, or sends unrelated data elsewhere.

  • Unknown downloads, IP-based endpoints, or unexplained external transmission
  • Credential, token, cookie, SSH, cloud-config, or browser-session access
  • Obfuscation, encoded payloads, dynamic evaluation, or hidden instructions
  • System-wide writes, elevated commands, persistence, or broad deletion
Critical boundary: this Skill is a manual decision framework. Its heuristics can over-report benign patterns, and a clean checklist result cannot cover runtime behavior, future updates, or files that were not inspected.

Use it for

Pre-install triage, permission review, and a documented human decision.

Do not claim

Automated malware detection, exploit validation, or guaranteed package safety.

Dependencies

Offline by default, network by choice.

Reviewing a local package needs only file-reading capability. The optional GitHub examples use command-line tools and public endpoints; they do not need an API key but remain subject to network access and anonymous rate limits.

Local review

Read the selected package and produce a report. No external service is required.

GitHub lookup

Optional examples use curl, jq, api.github.com, and raw.githubusercontent.com.

Delivery

A Markdown report for human approval before any install or execution step.
