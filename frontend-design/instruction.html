What to provide

Start with meaning.

A useful brief gives the design something real to respond to. If the subject, audience, or page goal is missing, the skill chooses one concrete interpretation and states it before designing.

Subject

What world is this from?

The product, its materials, artifacts, vocabulary, and real content.

Audience

Who must understand it?

The people using the page, their context, expectations, and level of familiarity.

Single job

What must the page achieve?

The primary action or understanding the interface should make possible.

Recommended prompt

Use Frontend Design to create a responsive launch page for an independent field-recording archive. Its audience is documentary sound artists, and the page’s single job is to help them discover and preview location recordings. Ground the visual language in field notes, timestamps, weather observations, and acoustic texture. Explain the direction, critique generic choices, then implement the finished interface.

The working method

Two passes. Two critiques.

The process separates direction from execution so generic decisions can be caught before they harden into code, then checks the built result for quality and restraint.

Pass A / Direction

Brainstorm, compare, commit.

Build a compact design system from the brief, then test whether it could belong to any other product.

  1. Name a palette of four to six purposeful colors.
  2. Assign deliberate display, body, and utility type roles.
  3. Compare layout ideas with prose and compact wireframes.
  4. Choose one memorable signature element rooted in the subject.
  5. Revise any choice that reads as a familiar AI-design default.
Pass B / Build

Implement, inspect, remove.

Follow the selected direction exactly, spending visual boldness where it earns its place.

  1. Build hierarchy, typography, language, and behavior together.
  2. Match implementation complexity to the chosen vision.
  3. Check selector interactions, spacing, and responsive states.
  4. Protect keyboard focus and reduced-motion preferences.
  5. Critique the finished page and remove one unnecessary flourish.

Design decisions

Every choice carries content.

The skill treats visual design and interface writing as one system. Nothing is added merely because polished websites usually contain it.

Typography

Type roles create personality and hierarchy; they are not neutral containers for copy.

Structure

Rules, labels, numbers, and sections encode real relationships or sequence—or stay out.

Motion

One orchestrated moment can serve the subject better than scattered decorative effects.

Language

Plain, active, consistent words help users act; failure and empty states give direction.

Spend boldness in one place.

The signature is a single memorable element that embodies the brief. Everything around it stays disciplined enough to make that choice feel intentional.

What the skill delivers

Direction you can build.

The output is not a mood-board-only concept. It connects the rationale to a responsive, usable implementation in the requested frontend environment.

Design rationale

A subject-specific point of view

A stated subject, audience, page job, aesthetic thesis, and justified signature decision.

Token direction

Color, type, layout, and voice

A compact system with named colors, clear type roles, layout logic, and writing register.

Implemented frontend

Production-oriented interface code

The page or component built in the project’s stack, using real content and deliberate structure.

Quality pass

Responsive and interaction details

Mobile behavior, focus visibility, reduced motion, spacing, selector integrity, and final self-critique.

Best fit

Use it when identity matters.

This skill adds the most value when a product needs a genuine visual position, especially after generic proposals have failed to capture its subject.

Strong use cases

  • New landing pages, product surfaces, portfolios, and editorial experiences
  • Existing interfaces that feel interchangeable or visually unfocused
  • Briefs where typography, hierarchy, tone, and brand character matter
  • Frontends that need concept, critique, implementation, and responsive polish together

Not the whole answer

  • It does not replace user research, product strategy, or accessibility auditing
  • It cannot infer unavailable brand assets, legal permissions, or hidden requirements
  • It should not override an explicit design system or visual direction in the brief
  • It is unnecessary when only a narrowly specified mechanical code edit is requested

Dependencies & limits

Context sets the ceiling.

Better decisions depend on access to the actual product brief, content, project code, runtime constraints, and any existing design language.

Keep these boundaries visible

Project stack

Implementation must follow the framework, component patterns, and build tools already in scope.

Assets & rights

Fonts, images, marks, and other media still require suitable files and permission to use them.

Accessibility

Focus and reduced motion are a quality floor; full conformance still requires dedicated testing.

Validation

Final quality should be checked in the real browser, target widths, and production build environment.

Specific beats polished-but-interchangeable.
