Prerequisites

Begin after discovery.

Variant analysis needs a known issue and enough understanding to describe why it is vulnerable. It is not the first pass for an unfamiliar codebase.

Known issue

A confirmed original

Bug or vulnerability location, vulnerable code, expected protection, and evidence that the issue is real.

Root cause

Conditions, not symptoms

Dangerous operation, attacker-controlled data, missing control, enabling context, and exploitability conditions.

Search scope

The complete codebase

Repository root, relevant languages and frameworks, generated or test-code policy, and available analysis tools.

Recommended prompt

Use Variant Analysis after this confirmed authorization bug. First state the root cause and exploitability conditions. Create an exact pattern that matches only the original, then generalize one element at a time across the entire repository. Run each pattern, review every new match, track true and false positives, stop if the false-positive rate exceeds roughly 50%, and return the final query plus triaged findings with location, confidence, reachability, controllability, and priority.

Five-step process

Specific first. General only with evidence.

Each generalization is an experiment. The new matches decide whether the abstraction is useful, should be filtered, or must be reverted.

Understand the original

Identify the root cause, necessary control-flow and data-flow conditions, attacker control, missing validation, and what makes the path exploitable.

Create an exact match

Start with a literal ripgrep or equivalent pattern and verify that it matches exactly one location: the known issue.

Identify abstraction points

Separate meaningful constants, function families, argument positions, and required context from variable names and incidental syntax.

Iteratively generalize

Change one element, run against the whole codebase, review every new result, measure false positives, then keep, filter, or revert the change.

Analyze and triage

For each match, record file, line, function, confidence, reachability, input controllability, missing protection, impact, and priority.

±1

Change one abstraction at a time. Otherwise you cannot tell which change introduced value—or noise.

Abstraction ladder

Climb only as far as the hunt needs.

The right level depends on the goal. Verification favors specificity; full assessment may justify semantic flow analysis and a larger manual triage burden.

Level 0

Exact match

Confirm the original and establish a zero-noise baseline.

Level 1

Variable abstraction

Replace incidental names to find copy-paste variants.

Level 2

Structural abstraction

Generalize the surrounding code shape while retaining important context.

Level 3

Semantic abstraction

Model sources, sinks, barriers, and flow for broad coverage.

≈50%

Default stop line: if false positives exceed roughly half the matches, revert or choose a different abstraction.

Automation needs much stricter precision than an analyst-led research hunt.

Tool selection

Use the lightest tool that can express the property.

Tool loyalty is an anti-pattern. A productive campaign can use ripgrep for recon, Semgrep for fast structural iteration, then CodeQL only where cross-function flow matters.

ReconZero setup

ripgrep

Fast exact and surface searches across the repository. Ideal for the baseline, literal families, hotspots, and quick scope checks.

Text matching cannot prove data flow, reachability, or exploitability.

StructureNo build

Semgrep

Readable structural rules, metavariables, exclusions, and taint mode. Useful on incomplete or non-building code.

Framework semantics, sanitizers, and complex interprocedural paths need careful modeling and review.

Deep flowSetup required

CodeQL

Best suited to cross-function and path-sensitive source-to-sink analysis when the required project database and language support are available.

Higher setup and query-modeling cost makes it a deliberate escalation, not the automatic first step.

Included starting resources: Semgrep and CodeQL templates for Python, JavaScript / TypeScript, Java, Go, and C / C++, plus a structured variant-analysis report template. These are starting points: sources, sinks, barriers, frameworks, and exclusions must be tailored to the actual root cause and codebase.

Deliverables

A reproducible hunt, not a pile of matches.

The output preserves how the query evolved and why each result was classified, so another analyst can reproduce the search and challenge its assumptions.

Root-cause model

Original vulnerability record

Bug ID, code location, vulnerable operation, attacker-controlled input, missing protection, enabling context, and exploitability conditions.

Pattern ledger

Each pattern version, tool, abstraction change, match count, true positives, false positives, filters, and decision to keep or revert.

Reusable analysis

Final query or rule

Appropriate use

A follow-on analysis skill.

Use it when one issue reveals a repeatable security property. Choose a different workflow when the first job is understanding the system or discovering an initial vulnerability.

Use it for

  • Hunting related instances after a vulnerability is confirmed
  • Checking whether a narrow fix missed variants elsewhere
  • Building and refining ripgrep, Semgrep, or CodeQL searches
  • Systematic audits centered on a known root-cause pattern
  • Expanding into related semantics, null edges, logic inversions, and documentation mismatches

Do not use it for

  • Initial vulnerability discovery without a known pattern
  • General code review or deep comprehension of unfamiliar code
  • Treating every static match as a confirmed vulnerability
  • Searching only the module that contained the original bug
  • Authoring remediation guidance as the primary task

Dependencies & limits

Coverage is a claim that needs evidence.

Static patterns surface candidates. Confirmation still requires code context, reachability analysis, input-control reasoning, sanitizer review, and sometimes runtime testing.

Keep these boundaries visible

Tool availability

ripgrep is the lightest path; Semgrep and CodeQL must be installed and configured. CodeQL generally needs a compatible database and language model.

Model accuracy

Generic source, sink, and sanitizer templates may be wrong for the application. Customize them before relying on results.

False negatives

Dynamic dispatch, reflection, generated code, framework magic, alternate languages, or misunderstood semantics can hide variants.

Finding status

A match is a review candidate. Confidence and priority do not replace exploitability validation or a full security assessment.

Understand why. Search everywhere. Generalize carefully. Triage everything.
