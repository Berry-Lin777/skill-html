Illustrative review rubric

Seven dimensions, weighted for a future run.

These percentages define how an executed benchmark would be scored. They are weights—not observed performance scores.

18% weight

Root-cause fidelity

The search model preserves source, sink, missing protection, and enabling context.

14% weight

Exact-match precision

Level 0 isolates the known issue before any abstraction begins.

15% weight

Controlled abstraction

One element changes per iteration and every new match is reviewed.

14% weight

Whole-repo coverage

Search scope spans the codebase rather than the original module alone.

14% weight

False-positive control

Noise is measured, explained, filtered, and stopped near the audit threshold.

12% weight

Query validity

Rules parse, run in the intended analyzer, and preserve relevant language semantics.

13% weight

Triage completeness

Location, confidence, reachability, control, protection, and priority are recorded.

Gate A

Known issue reproduced

The exact baseline must match the original once before broader search results count.

Gate B

Entire repository searched

A module-only run cannot support a codebase-coverage claim.

Gate C

Noise below stop threshold

If false positives exceed approximately 50% in an audit context, revert or refine.
