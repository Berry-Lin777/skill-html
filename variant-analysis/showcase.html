Specimen 00 · Known issue Baseline 
user_id = request.args.get("id")
query = "SELECT * FROM users WHERE id=" + user_id
cursor.execute(query)
Root-cause statement
“Attacker-controlled request data reaches a SQL execution sink without parameterization.”

Synthetic location: app/routes/users.py:42. The statement captures source, dangerous operation, and missing protection rather than a variable name or visual symptom.

Source

Externally controlled

The value comes directly from a request query parameter.

Sink

Database execution

The constructed string is passed to cursor.execute.

Protection missing

No parameter binding

String concatenation places input into SQL syntax without a bound parameter.

Controlled abstraction

Change one element. Review every new match.

The ladder illustrates pattern design. Only the exact-search method is locally available without extra tooling; Semgrep and CodeQL stages are not represented as executed scans.

Level 0

Exact literal baseline

Keep the table, parameter name, request accessor, and concatenation structure specific.

rg 'SELECT \\* FROM users WHERE id=.*request\\.args'
Exact
Level 1

Abstract variable names

Preserve request input and SQL concatenation while allowing different local identifiers.

$VALUE = request.args.get(...); $QUERY = "..." + $VALUE
One change
Level 2

Abstract query structure

Keep string construction followed by execution, but permit other tables and selected columns.

$QUERY = "..." + $INPUT; ...; cursor.execute($QUERY)
Review all
Level 3

Model source-to-sink flow

Track request inputs into SQL execution and recognize parameterization as a sanitizer.

source: request.* → sink: execute(...) → exclude: bound parameters
Not run here
>50%

Stop when the false-positive rate becomes unacceptable.

The skill’s default audit threshold is approximately 50%. If a generalization crosses it, revert the last abstraction or add a filter rather than continuing toward a noisier pattern.
