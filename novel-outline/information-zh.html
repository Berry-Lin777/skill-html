THE ARCHIVE · OUTPUTS

一本小说进去，短剧改编大纲五件套出来

创意不再分散在几次对话、几张表和人工补写的统计里。核心改编结构统一进入一份可以持续校验和渲染的 outline.json。

改编说明

一句话核心、保留／砍掉／合并三张表、风险对策和决策结论。关键取舍附原文证据。

人物表

主角组、重要配角、功能性角色分档；记录原著对应谁、合并了谁和人物弧。

爽点表

major/minor 分级、逐集落点，控制爽点间隔，避免中段出现真空区。

分集梗概

每集三栏：梗概、钩子、悬念。缺一栏视为未完成；保持叙述体，不越界写台词。

资产清单

由脚本自动汇总角色、场景、道具、出现集、复用方案和生成难点，而非让模型手写。

Markdown

供创作者阅读、修改和批注。

JSON

作为后续 Skill 与生产流程的数据底稿。

HTML

双击打开的单页评审报告。

THE INSPECTION · 14 GATES

14 道门，全部是代码审核

Checklist 交给模型自觉是靠不住的。每一道门都是 validate 里的确定性检查，不是写给模型阅读的提醒文字。

质量门默认阈值／检查内容
主角组1–5 人；男女主与主反派
重要配角有名字的重要配角 ≤ 10 人
功能性角色≤ 10 人；占脸不占名，使用称呼标签
主场景上限4 + ⌈集数/10⌉，限制在 5–15 个之间
叙事道具默认 ≤ 8 件；未填写 props 时明确标记跳过
一次性场景必须提供资产复用或改造方案
爽点间隔默认 ≤ 3 集，无真空区
第一集钩子必须存在
大爆点时机最早的 major 不能首次压到最后一集
每集三栏梗概、钩子、悬念全部必填
多人同框三人以上必须提供拆解方案
生成难点扫描雨戏、肢体接触、人群、手部特写等并进入预警
引用完整无失业角色、无空转场景、无零集道具，所有 ID 存在
梗概形式叙述体，无引号对白，不提前写成剧本

阈值可以通过 params.thresholds 按平台覆盖，无需修改代码。自测中每一道门都有击穿用例，证明它确实能拦截错误。

为什么角色需要分档

一刀切会混淆两件事：观众需要记住多少角色，以及制作需要维护多少张角色脸。主角组上限控制记忆负担；配角与功能性角色上限控制 AI 角色资产成本。无名背景人物不进入表，不追踪、不限量。

为什么 AI 短剧的场景上限更宽

AI 场景没有传统实拍的搭景经济学。场景门主要控制的是跨集一致性资产成本和观众的空间认知负担；在可控范围内保留更多场景，反而能提高视觉多样性。

THE CHECKPOINT · USER DECISION

流程中最值钱的一步：先拍板，再细化

快版骨架必须先交给用户确认三件事：砍了哪条线、合并了哪些人、大爆点落在哪几集。写分集前必须通过 validate --stage beats。如果节奏或 major 时机错误，会在这一阶段直接拦截。

DRAMATURGY REVIEW

为什么要暂停？

快版错了只损失一轮骨架；分集全部写完才发现方向错误，前后人物、钩子、场景与资产都会一起返工。分集本身也分批生成，每批不超过 10 集，防止后半段节奏崩塌和人物漂移。

THE PRODUCTION DOSSIER · REPORT

一页报告，把创作决策与生产需求铺开

报告面向业内评审，页面宽度 1600，内容平铺并支持 Cmd + F 搜索。它不是漂亮截图，而是一份可操作的生产诊断书。

KPI 数据带

总集数、爽点、角色分档、主场景、生成难点和改编幅度，六张卡快速看全局。

爽点节奏

大爆点实心、常规爽点浅色、空档直接标轴；超过阈值变成铁锈红，长剧自动折行。

分集概览

三列卡片，展示梗概、爽点、钩子、悬念、场景、角色与预警标签。

场景概览

每个场景的出现集、承载爽点、出场角色，以及一次性场景的复用方案。

关键决策

砍线结论、合并角色、角色位统计和 major 爆点落点由结构数据自动生成。

每集调度矩阵

角色与场景放在同一张网格中，纵向读取一列就能知道某一集要谁、在哪里生产。

资产量折算

三档角色、场景环境、叙事道具和生成难点自动折算为生产工作量。

质量门与导出

页眉徽章、病灶横幅、完整门清单和 JSON 导出；修改后可直接重新 render 与 validate。

THE EVIDENCE · TRACEABILITY

每个关键改编决定的出处，都能追溯回小说原文

重要保留项必须给出 keep[].evidence，让改编依据不是模糊的“原著里好像有”，而是能够逐字返回源文本核对。

What · 保留什么

杜十娘主动设计三百两赎身局，并暗中承担一半赎金

Why · 为什么保留

这是她从被交易者转为行动者的第一步，也是后续识人悲剧的基础。

Evidence · 原文证据

妾所卧褥褶内藏有碎银一百五十两，此妾私蓄，郎君可持去。三百金，妾任其半，郎君亦谋其半。

不是凭书名改编，也不是凭印象补剧情。

THE DIAGNOSIS · EXISTING OUTLINES

已有大纲，也可以直接做结构体检

不必重新生成。把已有方案整理为 outline.json，运行 checkup 即可检查角色、场景、爽点、钩子、悬念和引用关系。未通过不会阻止 HTML 渲染，因为体检模式的目标正是把病灶展示出来。

node scripts/novel-outline.mjs checkup outline.json node scripts/novel-outline.mjs render outline.json --html > outline-report.html

超长小说也能处理

80 万字无法一次塞入上下文时，chunk 根据章节标题自动分卷，默认每卷 15 章；各卷形成中间摘要后统一汇总。识别不到章节则按字数切分，最多 60 卷，超出时明确返回 truncated。

THE NEXT ACT · PRODUCTION PIPELINE

一份大纲，同时服务人和机器

创作者

获得明确的分集结构、爽点规划和可追溯改编依据；修改后能自动发现前后断裂。

制片与编剧团队

剧本开写前确认方向，提前看到人物、场景、资产规模与生成难点，减少理解偏差。

AI 短剧流程

统一 ID 减少名称漂移，outline.json 直接进入角色、美术、剧本和分镜的下游生产。

与 novel-characters 的分工

novel-outline 管改编结构：砍线、合人、安排爽点与分集；novel-characters 管人物画像、形象提示词、音色提示词和角色设定图。大纲位于角色制作的上游，人物清单无需在下一阶段重新判断。
