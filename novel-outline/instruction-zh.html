ACT I · Orientation

这不是一句提示词，而是一套改编工作流

novel-outline 接收小说原文和目标参数，完成砍线、合人、爽点安排、分集设计和制作资产统计。它先让你确认方向，再批量生成；最终结果同时给人阅读、给团队评审，也给后续 Skill 继续读取。

OUTPUT 01

改编说明

一句话核心、保留／删除／合并、风险对策，以及能够追溯到原文的逐字证据。

OUTPUT 02

人物与爽点

角色分档、人物弧、主次爆点和逐集落点，避免角色膨胀与节奏真空。

OUTPUT 03

分集梗概

每集包含梗概、钩子和悬念；使用叙述体，不提前越界写成台词或分镜。

OUTPUT 04

制作资产

自动汇总角色、场景、叙事道具、出现集、复用方案与生成难点。

不只是帮你写完一份大纲，而是把小说改编变成一套可以拍板、质检和继续生产的标准化流程。
ACT II · Source Material

第一步：准备小说原文

你可以上传 TXTMarkdownPDF 转文本，也可以提供明确的公版原文来源。受版权保护的作品应使用你有权处理的文本。

不只适用于一种小说

从奇幻学院、东方幻想、家族情感，到古典爱情与悬疑惊悚，只要提供可用原文和明确目标，都会进入同一套结构化流程。

东方幻想
家族情感
古典爱情
悬疑惊悚
长篇小说如何处理？
当原文无法一次进入上下文，先用 chunk 按章节分卷，默认每 15 章一卷；识别不到章节时按字数切分。最多 60 卷，超过时会明确返回 truncated，不会静默丢失结尾。

每个关键改编决定的出处，都能追溯回小说原文

核心保留项写入 keep[].evidence，并附逐字原文证据。这样可以核对改编依据，减少凭书名脑补、人物关系误读与记忆错误。

SOURCE EVIDENCE · 杜十娘

保留什么

杜十娘主动设计三百两赎身局，并暗中承担一半赎金。

为什么保留

这是她从被交易者转为行动者的第一步，也是后续识人悲剧的基础。

原文证据

妾所卧褥褶内藏有碎银一百五十两，此妾私蓄，郎君可持去。三百金，妾任其半，郎君亦谋其半。

ACT III · Dramaturgy Review

第二步：先拍板，再细化

这是流程中最值钱的一步。完整分集开写前，先生成快版骨架，只确认三个决定：砍了哪条线、合并了哪些人、大爆点落在哪几集。

向 Agent 发出任务

上传原文，并说明总集数、单集时长、题材、改编幅度和必须保留的情节。

使用 novel-outline Skill，将《杜十娘怒沉百宝箱》改编成 10 集竖屏短剧，每集约 2 分钟。保留悲剧结局，强化杜十娘的主动筹谋。先生成并校验快版骨架，展示砍线、合人和大爆点安排，等待我确认后再写完整分集。

Skill 读取原文并生成骨架

骨架包含 adaptation、characters、scenes 和 beats，暂时不写完整 episodes。

运行节拍阶段校验

node scripts/novel-outline.mjs validate outline.json --stage beats

如果爽点间隔、首集钩子或 major 爆点时机有问题，会在分集写作前直接拦截。

用户拍板

检查删减、合并和爆点落点。确认无误后回复“通过”；英文工作流回复 “Approved”。

生成完整十集并跑全量质检

每批最多 10 集，合并后运行 full validation，直到 14 道门全部通过。

CHECKPOINT · USER APPROVAL REQUIRED

为什么不能跳过拍板？

快版错了只损失一轮骨架；如果 60 集写完才发现主线、人物或爆点方向不对，整套内容都要返工。

ACT V · Structured Production Data

为什么要把大纲“代码化”

代码化不是为了让创作者写程序，而是把自然语言中的决定变成可统计、可校验、可追踪的生产数据。

统一 ID

角色、场景、道具分别使用稳定 ID，减少跨集名称漂移。

自动发现断裂

修改角色或场景后，校验器会指出仍在引用旧 ID 的分集。

自动计算资产

不用模型手写统计表，脚本直接计算出现集、次数和生产工作量。

继续进入下游

outline.json 可以继续供角色、美术和剧本 Skill 使用。

ACT VI · Terminal Lab

命令行：分卷、校验、体检、渲染

Agent 负责阅读小说与创作大纲；Terminal 工具负责确定性处理已经存在的文本或 outline.json。

按章节分卷

node scripts/novel-outline.mjs chunk book.txt /tmp/wk

校验大纲

node scripts/novel-outline.mjs validate outline.json # 可选阶段：--stage skeleton | beats | full

只运行 14 道质量门

node scripts/novel-outline.mjs checkup outline.json

生成报告与资产清单

node scripts/novel-outline.mjs render outline.json --html > outline-report.html node scripts/novel-outline.mjs render outline.json --html --lang en > outline-report.html node scripts/novel-outline.mjs assets outline.json

运行自测

node scripts/selftest.mjs
体检模式：已有大纲无需重新生成。checkup 会把问题明确列出；即使存在未通过项，HTML 报告仍可生成，因为目的就是展示病灶。

与 novel-characters 的关系

Appendix · Troubleshooting

常见错误：MODULE_NOT_FOUND

原因不是 Node 坏了，而是运行位置不对

命令中的 scripts/novel-outline.mjs 是相对路径。如果当前目录是用户主目录，Node 会去错误的位置寻找脚本。

解决方法

# 方法一：先进入包含 scripts/ 的 Skill 目录 cd /path/to/novel-outline node scripts/novel-outline.mjs checkup /absolute/path/to/outline.json # 方法二：直接使用脚本完整路径 node /absolute/path/to/novel-outline/scripts/novel-outline.mjs checkup /absolute/path/to/outline.json
