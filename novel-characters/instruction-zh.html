它做什么

一件事：把小说里的角色，整理成能直接开工的资产

novel-characters 处理一件事：你给它一篇小说或短故事，它把里面的角色整理成一套可直接开工的设定资产。每位角色会得到人物画像（每条描述附原文逐字引文）、形象出图提示词、音色提示词，以及一张 16:9 的角色设定图——左边是证件照式半身像，右上是全身三视图，右下是服饰道具的细节特写。

全部角色汇总成三份产物：结构化的 cast.json、一份 Markdown、一份双击就能打开的交互式 HTML 报告。

它的边界也很清楚：产出停在"角色长什么样、什么声音"这一层，不做分镜、不做动画、不做剧本。出图是可选环节，依赖本机 codex 的内置图像生成；没有 codex 也能跑完全流程，只是交付出图提示词而不出图。

16:9三区版式设定图（半身像 / 三视图 / 细节）
4 份产物：JSON · Markdown · HTML 报告 · 原图
2 套画风预设：半写实厚涂 / 吉卜力动画

开始前

三件事确认好，流程一次跑通

确认 Skill 可用

把 Skill 文件夹放进工作区后，让 Agent 自检一遍："检查一下 novel-characters 这个 skill"。它返回源码状态、脚本语法和样例校验结果——看到"样例全部通过校验"就可以开始。

准备小说文本

一个 .txt 文件即可，直接作为附件发给 Agent。像本教程这样上传《杜十娘怒沉百宝箱》的原文文件就可以。

想好产物放哪

可以在指令里指定输出文件夹；不指定的话，产物会放在原书同级的目录里。需要出图时，确认本机装有 codex（没有也能跑，只是不出图）。

第一步

一句话说明任务

不需要记任何参数。把小说文件发给 Agent，再用一句话说清目标就行，比如教程里这句：

用 novel-characters 分析《杜十娘》，提取主要角色，并生成角色设定图和报告。结果放到"03_真实运行素材"。

发出去之后，Agent 会自动走完全部环节：扫描全文识别人物、归并同一人的不同称呼、选出主要角色、逐位生成角色卡、做结构和引文校验、给每位角色出一张设定图，最后生成报告。完成后它会汇报角色数量、图片数量和产物链接——点开"交互式 HTML 报告"就能看到成果。

《杜十娘》这次运行识别出 5 位主要角色（杜十娘、李甲、孙富、柳遇春、杜妈妈），生成 5 张设定图。如果 Agent 报告有校验未通过或个别图片失败，它会说明修了什么、缺了哪张，按它的提示处理即可。

第二步

打开报告检查结果

产物一共四样，各管各的：cast.json 是给程序读的结构化数据；Markdown 是纯文本版角色设定集；report.html 是给人看的交互报告；images/ 文件夹里是每位角色的原始设定图。日常检查主要看 report.html。

报告是三栏工作台：左栏是故事摘要和按戏份排序的角色列表，主区一次看一位角色。点开一位角色，能看到她的完整画像——基本信息、外貌、性情、动机、人物弧光、与他人的关系，以及声音设计。

画像里最重要的是"原文依据"区。这里每一条都是小说里的逐字引文，说明这条设定不是模型编的。报告里所有提示词都带复制按钮——出图提示词、三视图提示词、反向提示词、中文对照、TTS 音色提示词各一个，点一下就能拿去喂 Midjourney 或 TTS 引擎。

左栏顶部的关系图谱把人物关系画成一张网：悬停某人亮出他的全部关系线，点关系列表跳到对应角色。用它快速确认人物关系有没有被理解错。

第三步

常见调整，都是一句话

只要最重要的几个角色

角色太多想先做核心的，一句话缩名单：

只为戏份最多的前 4 个角色制作角色卡和设定图。

Agent 会保留选中角色的完整设定，没选中的不会直接删掉——杜妈妈的卡片和图片被移进 work/excluded/ 文件夹留档，之后想恢复随时可以。

整体换画风

默认是半写实厚涂，想要动画质感一句话切换：

把所有角色改成统一的吉卜力动画风格。

换画风是全部设定图重新生成，原来的图会自动备份到 work/realistic-images-backup/，不会丢。所以建议先把名单和画风都想好再出图：名单可以随便缩（已有图直接复用），画风一动就要全批重出。

只要报告，先不出图

想先看文字设定再决定出不出图：

只生成角色分析和报告，这次不要出图。

这一步只花几分钟，报告内容与带图版完全一致，只是设定图位置留空。

对单个角色不满意

哪个不像只说哪个，其他角色不会被牵连：

李甲的三视图和半身像不太像，只重新生成李甲这一张。

Agent 只重生成这一张图并替换，角色名单和别人的图都不动。

配合上游大纲

如果你已经用 novel-outline 做过分集大纲，把 outline.json 一起给它，角色名单就直接沿用大纲拍板的结果，不会自己再加人、也不会改分档：

结合这份 outline.json 制作角色设定，不要改变角色名单。

产物

四个产物，四种用法

给人看

report.html

交互式报告，评审、讨论、核对设定都用它。画像、引文、提示词、关系图谱在同一页。

给程序

cast.json

结构化角色数据，角色码、分档、提示词字段都是稳定结构，外部工具改完还能喂回来重新渲染。

给协作

Markdown

纯文本版角色设定集，方便贴进文档、群聊和协作平台传阅批注。

给美术

images/

全尺寸 PNG 设定图，做参考图、喂一致性工具、进设定集排版都用它。

每位角色的提示词都有明确用途：出图提示词（含三视图版式）喂图像模型，反向提示词防止画风跑偏，TTS 音色提示词直接喂 Qwen3-TTS、ElevenLabs Voice Design 这类按文字设计音色的引擎。所有机器用提示词固定英文，人物画像和界面跟随你指定的报告语言。

边界

几种异常，都有明确处理

  • 小说超过 93 万字符：Agent 会明确告诉你尾部没有扫描到，不会悄悄漏掉——把书分成上下半卷分别处理即可。
  • 个别角色出图失败：流程不会中断，Agent 会在最后说明哪几位没出成，重发一句"补上失败的那几张"即可，已成功的不会重出。
  • 没有安装 codex：整个出图环节自动跳过，其余产物照常交付。
  • 担心误删：被缩名单排除的角色在 work/excluded/，换画风前的图在 work/realistic-images-backup/，都不用怕丢。
  • 跨图画风一致性：同一批图偶尔有观感差异，在意的话在指令里要求"以第一张为风格参考生成其余角色"。

检查清单

发起前的检查清单

  • 小说是 .txt 且内容完整。
  • 说清楚了要几位角色（不说就按默认来）。
  • 指定了输出目录（或者接受默认位置）。
  • 需要出图时，确认本机有 codex。
  • 拿到结果后先开 report.html 核对画像和原文依据，再取用提示词。
  • 发现哪位角色不对，用一句话只修那一位。
