What it does

One job: turn the characters in a novel into production-ready assets

novel-characters does one thing: give it a novel or short story, and it turns the people inside into a working character pack. Each character gets a profile (every trait backed by a verbatim quote from the text), an image-generation prompt, a voice prompt, and a 16:9 model sheet — ID-style bust portrait on the left, full-body three-view on the top right, costume and prop details on the bottom right.

Everything is packaged into three deliverables: a structured cast.json, a Markdown edition, and an interactive HTML report that opens with a double click.

The boundary is just as clear: output stops at "what each character looks and sounds like" — no storyboards, no animation, no scripts. Image generation is optional and uses the built-in image generator of local codex; without codex the full flow still runs, it just delivers prompts instead of images.

Before you start

Three checks, one smooth run

Make sure the skill is healthy

After dropping the skill folder into your workspace, ask the Agent to self-check: "Check the novel-characters skill in this folder." It reports source status, script syntax and sample validation — once "all samples pass", you are good to go.

Prepare the novel text

A single .txt file is all it takes — attach it to your message. This guide uses the full text of Pride and Prejudice.

Decide where outputs go

You can name an output folder in the request; otherwise results land next to the source book. For image generation, make sure codex is installed locally (the flow runs without it, minus images).

Step 1

Describe the task in one sentence

There are no parameters to memorize. Attach the novel file and state the goal in one sentence:

Use novel-characters to analyze Pride and Prejudice, extract the main characters, and generate character model sheets and a report.

The Agent then runs the whole pipeline on its own: scan the full text, identify characters, merge different names for the same person, pick the main cast, write each character card, run structure and quote validation, draw one model sheet per character, and finally generate the report. When it finishes, it reports character count, image count and links to every deliverable — open the Interactive report link to see the results.

In this run, 55 characters were identified and 10 main characters were fully profiled, each with a model sheet. If validation flags something or an image fails, the Agent explains what it fixed and what is missing — just follow its prompts.

Step 2

Open the report and check the results

There are four deliverables, each with its own audience: cast.json for programs, the Markdown edition for text workflows, report.html for people, and the images/ folder with full-size model sheets. Day-to-day checking happens in report.html.

The report is a three-pane workbench: the left pane holds the story summary and the cast ordered by importance; the main pane shows one character at a time. Open a character to see the full profile — basics, appearance, temperament, motivation, arc, relationships, and voice design.

The most important part of the profile is the source-evidence section: every entry is a verbatim quote from the novel, proving the trait was not invented. Every prompt carries a copy button — image prompt, three-view prompt, negative prompt, localized variant and TTS voice prompt — one click and it is ready for Midjourney or a TTS engine.

At the top of the left pane, the relationship graph draws the cast as a network: hover a character to light up all of their lines, click an entry in the relationship list to jump to that character. It is the fastest way to catch a misunderstood relationship.

Step 3

Common adjustments — all one-liners

Only the key characters

Too many characters? Shrink the list in one line:

Create character profiles and model sheets for only the four most important characters.

The Agent keeps the full profiles of those selected and never deletes the rest — deselected cards and images are moved into work/excluded/ for archiving, ready to restore anytime.

Switch the visual style

The default is semi-realistic painterly. For an animated look, one line:

Change all characters to a consistent Ghibli-inspired animation style.

Switching style regenerates every sheet; the previous images are backed up automatically to work/realistic-images-backup/. So settle the list and the style before generating: shrinking the list is free (existing images are reused), changing style re-runs the whole batch.

Report first, images later

Want the written profiles before committing to images:

Generate the character analysis and report without creating images.

This takes only minutes; the report is identical to the illustrated edition except the sheet slots stay empty.

One character looks off

Name only the character that needs work — nobody else gets touched:

Mr. Darcy’s portrait does not match his three-view model sheet. Regenerate only his image.

The Agent regenerates and replaces just that one sheet; the cast list and everyone else’s images stay untouched.

Work from an upstream outline

If you already made an episode outline with novel-outline, hand over its outline.json and the cast list follows the outline’s decisions — no extra characters, no re-tiering:

Use this outline.json to create the character designs. Do not change the character list.

Outputs

Four deliverables, four uses

For people

report.html

The interactive report for reviews, discussions and checking designs — profiles, quotes, prompts and the relationship graph on one page.

For programs

cast.json

Structured character data with stable IDs, tiers and prompt fields; edit it in external tools and feed it back for re-rendering.

For collaboration

Markdown

A plain-text edition of the character bible, easy to paste into docs, chats and collaboration platforms.

For artists

images/

Full-size PNG model sheets for reference boards, consistency tools and design-bible layouts.

Every prompt has a clear purpose: the image prompt (with the three-view layout baked in) feeds image models, the negative prompt keeps the style on rails, and the TTS voice prompt plugs straight into text-to-voice engines such as Qwen3-TTS or ElevenLabs Voice Design. All machine-facing prompts are fixed in English; profiles and the interface follow the report language you specify.

Limits

Known edge cases, all handled

  • Novel beyond 930K characters: the Agent tells you explicitly that the tail was not scanned — split the book into two volumes and run each.
  • An image fails: the run does not stop. The Agent lists who is missing at the end; send "regenerate the failed sheets" and successful ones are not re-run.
  • No codex installed: the image stage is skipped automatically; everything else is delivered as usual.
  • Afraid of losing work: excluded characters live in work/excluded/, pre-switch images in work/realistic-images-backup/ — nothing is silently dropped.
  • Cross-image style consistency: sheets in one batch can differ slightly; if it matters, ask the Agent to "use the first sheet as the style reference for the rest".

Checklist

Before you hit send

  • The novel is a complete .txt file.
  • You said how many characters you want (defaults apply otherwise).
  • You named an output folder (or accept the default location).
  • If you want images, codex is installed locally.
  • When results arrive, open report.html and check profiles and source evidence before lifting prompts.
  • If one character is off, fix just that one with a single line.
