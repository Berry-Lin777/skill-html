Give agent memory a structure you can inspect.

Ontology stores typed entities and relationships as a local append-only event log, then reconstructs the current graph for queries, traversal, and explicit validation.

What you gain

A memory model with visible parts, not an opaque pile of notes.

01

Named things

Represent people, projects, tasks, decisions, or your own entity types with stable IDs and property maps.

02

Meaningful links

Connect entities with directed, typed relations so an agent can answer “what belongs to this?” and “who owns that?”

03

Inspectible history

Mutations append JSONL events. The active graph is reconstructed from those events instead of being hidden in a hosted service.

Recommended workflow

Build the graph, ask the graph, then validate it explicitly.

Step 01

Choose a graph

Use a graph name under the skill’s data directory. Path containment rejects traversal outside that directory.

Step 02

Define types

Optionally add YAML schema rules for required fields, enums, relation types, cardinality, and acyclic relations.

Step 03

Append events

Create or update entities, add relations, and record logical deletes as events in the local JSONL ledger.

Step 04

Query & traverse

Filter active entities by type and properties, or follow relations to retrieve connected context.

Step 05

Run validation

Invoke validation as a separate review step and inspect its text output before accepting a mutation.

A good request

Provide concrete identities, types, properties, and the question you want answered.

Include these details

  • A graph name and stable entity IDs
  • Entity types and useful properties
  • Relation direction and relation type
  • The query or traversal to run afterward
  • Whether schema validation is required
Recommended prompt 
In the “studio” graph, remember the Atlas Redesign project, an open task named “Verify accessibility,” and Maya as the task owner. Link the task to the project and Maya, then return every open task related to Atlas Redesign. Run explicit schema validation and report any issues separately.

Delivered output

Small local artifacts that remain readable outside the agent.

Best suited to

Local agent memory, research maps, project context, decision records, dependency graphs, and other modest knowledge graphs that benefit from transparent files.

Not a database server

This is a file-backed CLI, not a concurrent graph database, access-control system, vector search engine, or automatic truth verifier.

Dependencies & limits

Know the boundary before treating the graph as trusted memory.

Python requirement

The source uses modern type syntax and requires Python 3.10 or newer. Core CRUD uses the standard library.

Schema requirement

Schema commands import PyYAML. Install it explicitly before using schema append or schema-aware validation.

Validation boundary

Mutations are appended before validation. The validator reports issues but currently returns a zero process exit code, so automation must parse and review the report.
