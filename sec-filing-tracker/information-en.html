Research that should take minutes is burning hours.

Writing research notes, running diligence, tracking competitors or following which companies mention an executive, a product or a phrase — it almost always comes back to SEC EDGAR.

EDGAR’s own full-text results are rough: rows come back without usable links, and company, form and date information is scattered across pages. So most people end up doing one of two things — opening a paid terminal, or copying a search result into Excel by hand, then adding links and company details back in, row by row.

General-purpose AI tools can generate a table in seconds — but they routinely invent company names, CIKs and form types that look completely real, and the links 404 the moment you click them.

The problem was never a lack of tools. It’s not being able to trust which links will actually open.

One request in. A verified, openable list out.

Give it the phrase you care about — quote it for an exact match — and optionally narrow by form type and date range.

SEC Filing Tracker calls SEC’s official EDGAR full-text search endpoint with a single, identified HTTP request and returns up to 100 hits. Documents inside the same filing collapse into one row, deduped by accession number, and EDGAR’s own relevance order is preserved end to end.

What comes back is row after row of real filing records: company, tickers, CIK, form type, filing date, accession number — plus a by-form distribution and the total match count. No guesswork, no fabricated fields.

The Skill does the tedious look-up, dedupe and link construction first, and hands every source and piece of evidence back to you. Your judgment stays yours — it simply makes the finding correct and the links real.

Everything you get — and the line it will never cross.

Each run is built so the only thing you still need to do is read the filing itself.

Every field comes from EDGAR’s official JSON

Company, tickers, CIK, form, date and accession number are copied or mechanically derived from EDGAR’s response — never inferred, never invented. Every value you receive can be checked verbatim on sec.gov.

Links are verified — and never guessed

A filing-index deep link is built only when a real CIK and a well-formed accession number are both present, and each one is re-verified as an HTTP 200 response; otherwise it falls back to the company’s filings browse page and flags url_kind. Links do not 404.

No API key of any kind

EDGAR’s full-text endpoint is anonymous, free and registration-free. The Skill sends only an identifying User-Agent and never reads, requires or accepts credentials.

One request per run — fair-access compliant by construction

Exactly one HTTP request per run, with results capped at 100 (EDGAR’s per-response ceiling), so the SEC’s 10 requests/second limit is satisfied by construction. No rate limits, no paging.

Deterministic offline runs

Offline mode runs the full pipeline — normalize, dedupe, cap, histogram — on fixture data; identical input yields byte-for-byte identical output. Ideal for CI and regression testing.

Built for people whose job is reading primary sources.

The point was never “it can search SEC too”. It turns a research hypothesis inside SEC’s primary disclosures into a set of audit-ready, machine-readable evidence candidates — fast, and far lighter than a research terminal.

It removes the recurring rhythm of research — search, copy, re-check the link, stitch a sheet by hand. The first search feeds the next step: widen or narrow from the by-form distribution, open the original from the accession number, keep tracking a phrase over time.
