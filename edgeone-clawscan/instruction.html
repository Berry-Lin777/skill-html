Four-part checkup

Each signal has a separate evidence boundary. Missing cloud intelligence must be reported as unavailable, never as “no vulnerabilities.”

01

Audit configuration

Interpret findings from the built-in OpenClaw audit as risk hints and recommend narrower exposure.

Deep mode can probe a configured Gateway.
02

Review Skills

Combine local file review with optional threat-intelligence lookups for installed Skills.

Cloud mode sends Skill name and source.
03

Match advisories

Query current CVE and GHSA signals using the literal product name and detected version.

Unavailable is not equivalent to clean.
04

Map privacy paths

Review configuration, approval state, and permission metadata without reading personal file contents.

No photo, document, or transcript contents.

Recommended request

Use an isolated or test environment first. Explicitly state the outbound policy and whether a live Gateway probe is authorized.

PROMPT 
Run an OpenClaw security checkup in an isolated test environment. Keep A.I.G cloud lookup disabled, do not probe any non-local Gateway, and report unavailable intelligence separately from verified findings.

Before you run

  • Verify that openclaw on PATH is the intended binary.
  • Review the configured Gateway before authorizing --deep.
  • Cloud lookup is on by default and sends limited metadata to Tencent A.I.G.
  • The packaged “off” control is an instruction to the Agent, not a shell-enforced network block.
  • Do not treat a checkup report as certification, penetration testing, or a guarantee.
