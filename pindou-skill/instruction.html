01 / Fit

For people who want to sit down and bead, not redraw a photo by hand.

Use it when a cat photo, a character, a game still, or a short text description should become a pegboard plan with real color codes.

Use it for

  • Pets, portraits, and simple objects you already have a photo of
  • Anime / game characters you are allowed to turn into craft art
  • Text-only ideas when you do not have a reference photo
  • A print-ready grid plus a color-code shopping list

Do not use it for

  • Photoreal 3D, embroidery, or cross-stitch charts
  • Exact manufacturer inventory beyond the bundled MARD 221 table
  • Silent re-rolls until the grid count is perfect — that burns API tokens
  • Skipping the pixel-draft review and hoping extraction “fixes” composition
02 / What you actually get

Reference, AI grid, then a sheet you can print.

The published cat run shows the whole handoff: a photo becomes a numbered pixel draft, then a cell-by-cell color-code pattern.

03 / Workflow

Five spoken steps. Two hard stops.

The agent talks in everyday language. It does not throw spec_lock or palette IDs at you. It does stop when a human decision is cheaper than another image call.

1Lock the briefStyle, grid size, background, max colors, must-keep details, and how many candidates to draw.
2Write spec.jsonThen spec_to_prompt.py turns it into the Chinese image prompt. You do not edit that text by default.
3Draw the gridPhoto → edit.py. Text only → generate.py. Both write a gridded ai_pixel.png.
4You pickRequired stop. Approve, retune, or re-roll. The chosen file becomes ai_pixel.png.
5Snap and printExtract median colors, Lab/CIEDE2000 snap to MARD, render pattern.png / .svg and bom.csv.
04 / Ask like this

Name the craft constraints, then ask it to pause.

Use pindou-skill on this photo.

Style: cartoon
Grid: about 36×36 — finer is fine if the face needs it
Background: keep the black backdrop
Max colors: 18
Must keep: green eyes, pink inner ears, brown ear patches
Candidates: 2

Pause at the AI pixel grid so I can pick one. If the drawn grid count
differs from the spec, show me accept / redraw / rewrite-spec. Do not
silently spend another image call. Then extract colors and give me
pattern.png, pattern.svg, and bom.csv.

No photo? Say so. The same brief goes to generate.py instead of edit.py. The extraction half of the pipeline does not change.

05 / Delivery

The print sheet is the product. The SVG is the edit copy.

pattern.png

Main print file: row/column numbers, a color code in every bead cell, and a right-hand shopping list. cell_px 40 is the A4-friendly default.

bom.csv

Code, hex, names, and counts. Background cells are omitted when the brief said solid or remove — empty cells are not sold as white beads.

pattern.svg

Editable groups for cells, grid lines, codes, and the BOM. Use this if you want to nudge a code or type size after the run.

06 / Setup and limits

You bring a Python env and an image API key.

RuntimePython 3.10+. Install openai, opencv-python-headless, numpy<2, scipy, scikit-image, pandas, pillow, and cairosvg if you want the PNG render. Without cairosvg you still get pattern.svg and bom.csv.
Image modelDefault endpoint is bianxie’s gpt-image-2. Point BASE_URL at api.openai.com and switch the model if you want the official API. Keys live in edit.py / generate.py or OPENAI_API_KEY / BIANXIE_API_KEY / IMAGE_API_KEY.
Grid count is a requestThe AI often misses the exact spec by 1–3 cells. The skill must stop and offer accept / redraw / rewrite-spec. Vague replies default to accepting the drawn grid.
Color science stays in LabRGB k-means is forbidden. Snap uses CIEDE2000. Extraction writes raw median RGB only; palette snap and max_colors happen later in svg_to_grid.py.
